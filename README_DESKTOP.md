> **تاريخ التحديث**: نوفمبر 2026

## 📌 1. نظرة عامة (Overview)

تم تحويل منظومة **OMS** الكاملة من مجرد مواقع ويب متفرقة إلى **تطبيق ديسكتوب حقيقي متكامل (Native Windows Desktop Application)** يعمل عبر إطار عمل **Electron**، مع الحفاظ على **نفس التصميم والواجهات الأصلية 100%**، وإضافة شاشة ترحيب واختيار للمنصات تحمل **الشعار الرسمي لشركة OMS (One Media Solution)**، مع **تشغيل خوادم الباك إند وقواعد البيانات تلقائياً في الخلفية بمجرد تشغيل ملف الـ `.exe`**.

---

## 🎨 2. ما تم إنجازه في التصميم وتجربة المستخدم (UI/UX)

### أ) شاشة البداية واختيار المنصة (Welcome & Portal Selection)
عند تشغيل التطبيق:
1. **عرض شعار OMS الرسمي**:
   - يظهر الشعار الرسمي `one media solution` في بطاقة بيضاء نقية مع ظلال ناعمة وإضاءة باللون الأحمر المميز.
2. **بطاقات الأقسام الثلاثة (Cards)**:
   - 📄 **قسم المحاسبة والفواتير (`Invoice`)**: دورة الفواتير المحاسبية، الضرائب (VAT & WHT)، الموافقات المالية، وسجلات المدفوعات والعملاء (منفذ `5173` / باك إند `5001`).
   - 📺 **قسم الميديا والإعلانات (`Media`)**: تخطيط ومتابعة الحملات الإعلانية، القنوات، الموردين، وهوامش الأرباح وتصدير Excel (منفذ `5174` / باك إند `5002`).
   - 🛡️ **بوابة الإدارة المركزية (`Admin`)**: إدارة حسابات الموظفين المركزية، ضبط الصلاحيات وتأمين النظام (منفذ `5175` / باك إند `5003`).
3. **مؤشرات اتصال حية (Live Health Badges)**:
   - نقطة حالة ذكية بجانب كل قسم (`🟢 متصل وجاهز` أو `🔴 غير متصل`) يتم تحديثها تلقائياً كل 4 ثوانٍ.

### ب) الشعار متواجد معنا دائماً (Continuous Branding)
* **في شريط العنوان المخصص (Custom Title Bar)**:
  - الشعار الرسمي موجود دائماً في الهيدر العلوي طوال فترة العمل.
  - زر **`🏠 اختيار المنصة`** يتيح الرجوع لشاشة الاختيار الرئيسية في أي وقت بنقرة واحدة.
  - أزرار التبويبات العلوية للتبديل اللحظي بين الفواتير، الميديا، والأدمن دون إغلاق النافذة.
  - أزرار التحكم بالنافذة المدمجة (تصغير، تكبير/استعادة، إغلاق)، أزرار التكبير/التصغير (Zoom)، وإعادة التحميل، وزر الطباعة المباشرة.
* **داخل صفحات تسجيل الدخول**:
  - تم تحديث صفحات تسجيل الدخول للأنظمة الثلاثة لتحتوي على الشعار الرسمي بجودة عالية.

## ⚡ 3. التشغيل التلقائي للباك إند داخل الـ EXE (Auto-Start Backends)

أصبح ملف الـ **`.exe`** يحتوي داخلياً على **منسق خوادم ذكي (Backend Orchestrator)**:
1. **تشغيل خدمة PostgreSQL**: يتم التأكد من إقلاع قاعدة البيانات تلقائياً.
2. **فحص وتشغيل الخوادم الثلاثة**:
   * خادم الفواتير (Invoice API) على المنفذ `5001`
   * خادم الميديا (Media API) على المنفذ `5002`
   * خادم الإدارة (Admin API) على المنفذ `5003`
3. **الإغلاق النظيف (Graceful Shutdown)**: عند إغلاق تطبيق الديسكتوب، يتم إنهاء كافة العمليات المشغلة في الخلفية تلقائياً لمنع استهلاك موارد الجهاز.

## 🛠️ 6. سجل كامل بالأخطاء التي واجهت تطبيق الديسكتوب وكيف تم حلها جذرياً (Troubleshooting Log)

فيما يلي توثيق دقيق لكل مشكلة برمجية حدثت أثناء بناء تطبيق الديسكتوب، والسبب التقني وراءها، وكيف تم حلها نهائياً:

### 1) خطأ: `ERR_CONNECTION_REFUSED` على المنافذ 5173 و 5174 و 5175
* **السبب التقني**: عند تشغيل برنامج الديسكتوب، كانت وسوم `<iframe>` تحاول الاتصال الفوري بتلك المنافذ قبل أن يكتمل إقلاع سيرفرات الـ Frontend.
* **الحل الجذري**:
  1. قمنا ببناء **خادم محلي مدمج خفيف (Built-in SPA Static Server)** داخل `desktop/main.cjs` يقدم ملفات الـ `dist/` المترجمة للأنظمة الثلاثة تلقائياً على نفس المنافذ.
  2. تفعيل **التحميل عند الطلب (Lazy Loading)** للإطارات؛ بحيث لا يتم استدعاء أي منفذ إلا عندما يضغط المستخدم على القسم المطلوب من شاشة البداية.

### 2) خطأ: `Cannot find module '@supabase/supabase-js'` في خادم الفواتير
* **السبب التقني**: كانت الحزمة مسجلة في `package.json` لخادم الفواتير لكن مجلد `node_modules` لم يكن يحتوي عليها محلياً.
* **الحل الجذري**:
  1. تثبيت حزمة `@supabase/supabase-js` فوراً في `Invoice/server`.
  2. تطوير `Invoice/server/src/prisma/prismaClient.ts` ليعتمد على عميل **`PrismaClient`** الرسمي المتصل مباشرة بقاعدة بيانات PostgreSQL المحلية بدلاً من الاعتماد على اتصال خارجي مقطوع.

### 3) خطأ: رسالة `"هذا الحساب غير مفعّل"` عند تسجيل الدخول
* **السبب التقني**: في ملف `admin/backend/src/index.ts` السطر 104، كانت نتيجة استعلام قاعدة البيانات عبر مكتبة `pg` تعود كمصفوفة `rows = [ { ... } ]`. وكان المطور السابق قد كتب:
  ```typescript
  const user = rows; // ❌ خطأ: rows مصفوفة
  if (!user.isActive) { ... } // user.isActive هنا دائماً undefined
  ```
  ولأن `!undefined` تساوي `true`، كان السيرفر يعتبر كل المستخدمين "غير مفعّلين" حتى حساب الأدمن النشط!
* **الحل الجذري**:
  تم تصحيح الكود بالكامل إلى:
  ```typescript
  const user = rows[0]; // ✅ استخراج أول صف من نتائج الاستعلام
  if (!user.isActive) { ... }
  ```
  كما تم تصحيح كافة نقاط الاستعلام في ملف الباك إند، وتأكدنا من أن جميع الحسابات في قاعدة البيانات نشطة ومفعّلة بنسبة 100% (`isActive: true`).

### 4) مشكلة: تشغيل الباك إند يدوياً في نوافذ منفصلة
* **السبب**: الحاجة لتشغيل ملفات `.bat` متعددة قبل فتح التطبيق.
* **الحل الجذري**:
  تمت إضافة دالة **`autoStartBackends()`** داخل كود Electron الرئيسي (`main.cjs`). تقوم الدالة تلقائياً بفحص منافذ الباك إند (`5001`، `5002`، `5003`) وقاعدة بيانات PostgreSQL، وإذا وُجد أي سيرفر متوقفاً، يتم تشغيله في الخلفية بدون نوافذ مزعجة، مع إنهاء عملها تلقائياً عند غلق البرنامج.

### 5) مشكلة: توجيه مسارات الـ API بين السحابي والمحلي
* **السبب**: كانت واجهات الفواتير والميديا تشير إلى روابط Vercel السحابية، وواجهة الأدمن تشير إلى `/api`.
* **الحل الجذري**:
  تم تعديل ملفات `api.ts` في الواجهات الثلاث للتحقق الذكي:
  إذا كان التطبيق يعمل محلياً (`localhost` / `127.0.0.1` داخل الديسكتوب)، يتم التوجيه تلقائياً إلى الخوادم المحلية:
  * الفواتير: `http://127.0.0.1:5001/api`
  * الميديا: `http://127.0.0.1:5002/api`
  * الإدارة: `http://127.0.0.1:5003/api`

### 6) تعارض المنفذ في قسم الميديا (Port Collision)
* **السبب**: كان ملف `media/backend/.env` يحتوي على `PORT=5001`، وهو نفس منفذ قسم الفواتير.
* **الحل الجذري**:
  تم ضبط منفذ الميديا ليكون `PORT=5002` وفصل المنافذ تماماً لمنع أي تضارب.

### 7) أيقونة برنامج الـ EXE
* **الحل**: تم توليد ملف أيقونة Windows كامل المواصفات (`icon.ico`) متعدد الأحجام (16x16 حتى 256x256) من شعار شركة OMS المرفوع ودمجه في النسخة المحمولة والمثبت الرسمي.
